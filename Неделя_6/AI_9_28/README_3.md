## Как этим пользоваться

### Полностью локальный RAG — один флаг

```bash
./run.sh --rag --local-gen --user alice
```

Что происходит на каждом вопросе:

```
вопрос
  → обогащение из памяти задачи (цель, термины)
  → retrieval: BM25 ⊕ dense → RRF → реранк → MMR → порог     (эмбеддинги Ollama bge-m3)
  → блок [rag] в промпте
  → ГЕНЕРАЦИЯ ЛОКАЛЬНОЙ моделью                                (LM Studio, Qwen2.5-Coder-3B Q6_K)
  → источники [doc_id#chunk_id] + цитаты + grounding
```

Внешних HTTP-запросов в такой сессии нет ни одного.

### One-shot режимы

```bash
./run.sh --rag-ask "как считается бюджет токенов" --local-gen
# → ответ + список источников + дословные цитаты — всё локально

./run.sh --rag --local-gen --rag-grounding strict --user alice
# → строгая проверка опоры: при провале — одна авто-перегенерация
```

### Переключение генератора на лету

```
> /gen status
[Генерация] lmstudio/Qwen2.5-Coder-3B-Instruct-Distill-Qwen3-Coder-Next-abliterated-Q6_K
            профиль rag-strict (temperature 0.1, max_tokens 700, ctx 8192)

> /gen cloud
[Генерация] переключено на cloud:stepfun/step-3.5-flash

> /gen local
[Генерация] переключено на lmstudio/Qwen2.5-Coder-3B-Instruct-…-Q6_K
```

`/gen status` токенов не тратит.

### Команды и флаги дня

| Команда / флаг | Действие |
|---|---|
| `--local-gen` | retrieval локальный + **генерация локальной моделью** |
| `--gen-provider {cloud,ollama,lmstudio}` | явный генератор для RAG |
| `--gen-model <id>` | конкретная модель-генератор из реестра |
| `/gen local` / `/gen cloud` | переключить генератор RAG в сессии |
| `/gen status` | кто генерирует сейчас (модель + профиль) |
| `AI9_GEN_PROVIDER`, `AI9_GEN_MODEL` | то же через переменные окружения |

## Сравнение: локальная против облачной

Один и тот же датасет, один и тот же retrieval, различается **только генератор** —
иначе сравнение было бы нечестным.

```bash
python -m rag.compare \
  --queries rag/datasets/queries.jsonl \
  --modes cloud,local \
  --k 5 --repeat 3 \
  --report dev/logs_reports/stages/rag_local_compare.md
```

### По каким трём осям меряем

| Ось | Что именно измеряется |
|---|---|
| **Качество** | покрытие `must_contain`, наличие и валидность ссылок `[doc_id#chunk_id]`, `grounding.verdict` (`ok` / `partial` / `hallucination` / `insufficient`), hit-rate@5 retrieval (одинаков у обоих — retrieval не менялся) |
| **Скорость** | время до первого токена и полная латентность, медиана и p95 по 3 повторам, токены/с |
| **Стабильность ответов** | доля ответов с ошибкой / пустых / с таймаутом, дисперсия латентности, **совпадение факта при трёх повторах одного вопроса** (самопротиворечивость) |

> **Не путать:** здесь измеряется *стабильность ответов модели*. Устойчивость сервиса
> под параллельной нагрузкой — это отдельная метрика и другой день (доступ извне).

### Что получилось

| Ось | Облако `step-3.5-flash` | Локально `Qwen2.5-Coder-3B Q6_K` |
|---|---|---|
| Ответы с валидными источниками | 10/10 | 9/10 |
| `grounding.verdict = ok` | 9/10 | 7/10 (2 — `partial`) |
| Латентность, медиана / p95 | ~2,8 с / ~6,1 с | ~9,4 с / ~21 с |
| Токенов в секунду | зависит от сети | ~11 ток/с (CPU, GPU нет) |
| Ошибок / пустых / таймаутов | 1 (429 от провайдера) | 0 |
| Факт совпал в 3 повторах | 9/10 | 8/10 |

**Вердикт.** По фактологии локальная модель не хуже на прямых вопросах «что делает X»
и уступает на вопросах, требующих связать два документа. Проигрыш по скорости
в ~3 раза ожидаем: inference идёт по CPU, дискретного GPU на хосте нет. Зато
локальный контур не зависит от сети и лимитов провайдера — облачная строка с `429`
это же и показала.

Полная таблица «вопрос × (cloud / local)», сводка по трём осям и разбор трёх
расхождений — в `dev/logs_reports/stages/rag_local_compare.md`.

## Как устроено

### Генератор инжектится, а не выбирается внутри RAG

```python
# rag/service.py — РАСШИРЕНИЕ
RagService(cfg, llm=..., embedder=...)
service.answer(question, use_rag=True, llm=None)
#   llm передан  → генерирует он
#   llm = None   → генерирует self.llm
```

**Смену модели `rag/` не делает.** Реестр моделей знает только `Kod.py` — иначе в
`rag/` появилась бы вторая точка правды о том, «какая модель сейчас боевая»,
и она неизбежно разошлась бы с `/model`.

### Одна точка переключения

Флаг `--local-gen` (и `/gen local`) собирает клиента из `ModelRegistry` и подставляет
его **одновременно** в `agent.llm` и в `rag_service.llm`. Поэтому не бывает ситуации,
когда агент отвечает локальной моделью, а RAG — облачной, или наоборот.

### Конфигурация — `rag/config.json`, секция `generation`

```json
{
  "generation": {
    "provider": "cloud",
    "model": null,
    "profile": null
  }
}
```

- `provider: "cloud"` — дефолт, поведение прежнее;
- `model: null` — брать модель из реестра (`ModelRegistry`), а не дублировать имя здесь;
- `profile: null` — использовать профиль самой модели из реестра (у боевой 3B это
  `rag-strict`). Если профиль не задать вовсе, локальная модель генерирует без лимита
  токенов и упирается в таймаут — на этом пойманы первые прогоны.

Переопределения: `--gen-provider`, `--gen-model`, `AI9_GEN_PROVIDER`, `AI9_GEN_MODEL`.

### Индекс не трогали

Эмбеддинги делает Ollama `bge-m3` — она была локальной и раньше. Меняется только то,
**кто пишет ответ**, поэтому индекс 117 чанков / 9 документов остаётся прежним,
а `meta.json` сверяется с конфигом (несовпадение → плановый ребилд с записью в журнал).

### Истинный офлайн

Проверка «работает без сети» сделана по-настоящему: интернет на хосте выключался,
и агент продолжал отвечать по индексу. Это и есть «приватный сервис доступен всегда»:
запросы с конфиденциальными данными физически не покидают компьютер.

## Границы (чего специально нет)

- **`rag/` не импортирует `core/`, `core/` не импортирует `rag/`** — связь только через
  DI-фасад в `Kod.py`, как и раньше.
- **`rag/` не выбирает модели** — реестр знает только `Kod.py`.
- **Индекс не пересобирается** без явной необходимости.
- **`TaskStage` не затронут** — локальная генерация не создаёт записей в `transition_log`.
- **Без `--local-gen` промпт и поведение байт-в-байт прежние**; без `--rag` модуль `rag/`
  вообще не импортируется.
- **Новых pip-зависимостей нет** — локальные клиенты живут на `requests`.
- **Сравнение не на заглушках** — обе колонки таблицы получены живыми прогонами;
  mock допускается только как однократный «прогрев» и помечен как mock.

## Запуск

```bash
# Полностью локальный RAG
./run.sh --rag --local-gen --user alice

# Ответ по индексу без входа в REPL
./run.sh --rag-ask "как устроен запрет перехода без утверждённого плана" --local-gen

# Только поиск, без генерации (латентность retrieval)
./run.sh --rag-search "что такое дозированная доставка"

# Сравнение локальной и облачной модели
python -m rag.compare --queries rag/datasets/queries.jsonl \
  --modes cloud,local --k 5 --repeat 3 \
  --report dev/logs_reports/stages/rag_local_compare.md

# Облачный RAG (прежнее поведение)
./run.sh --rag --user alice
```

Перед локальными прогонами оператор поднимает оба сервиса:

```bash
# LM Studio — генерация
~/.lmstudio/bin/lms server start
~/.lmstudio/bin/lms load mradermacher/Qwen2.5-Coder-3B-Instruct-Distill-Qwen3-Coder-Next-abliterated-GGUF:Qwen2.5-Coder-3B-Instruct-Distill-Qwen3-Coder-Next-abliterated.Q6_K.gguf --gpu 0 --context-length 8192

# Ollama — эмбеддинги (чат на ней не обязателен)
curl -s http://127.0.0.1:11434/api/tags
```
