## Суть проекта

CLI-агент (RouterAI, модель `stepfun/step-3.5-flash`) с **явной моделью памяти**,
**настраиваемой персонализацией**, **формализованным состоянием задачи**, **набором
неизменяемых правил (инвариантов)**, **контролируемым жизненным циклом задачи**,
**подключением к внешнему миру через MCP** (внешний источник инструментов) и —
главное для Дня 24 — **RAG-ответом с обязательными источниками, цитатами и
анти-галлюцинационным режимом «не знаю»**.

RAG (Retrieval-Augmented Generation) — паттерн дополнения ответа LLM **нашими**
знаниями прямо во время инференса. День 24 делает ответ **проверяемым и честным**:
каждый ответ сопровождается **списком источников** (`source` + `section/chunk_id`) и
**цитатами** — дословными фрагментами найденных чанков, подтверждающими смысл ответа.
Если релевантность найденного **ниже порога**, ассистент **обязан** сказать «не знаю»
и попросить уточнение, а не сочинять ответ «из головы».

Центральная функция ответа после переработки под День 24:

```
answer(вопрос, use_rag=True) -> Answer
  1. retrieval:  retrieve(вопрос) → чанки + их релевантность (score)
  2. gate:       max(score) < threshold  →  «Не знаю. Уточните вопрос, пожалуйста.»
  3. LLM:        llm.complete(промт с чанками, обязателен формат)
  4. render:     ответ  +  sources[] (source + section/chunk_id)  +  quotes[]
  5. verify:     смысл ответа ⊆ цитаты (grounding) → ok | partial | hallucination
```

Пайплайн строкой (как в постановке дня): **ответ + список источников + цитаты**,
а при слабом контексте — **«не знаю»**.

Ключевые границы:

- **Источники и цитаты обязательны**: без них ответ не считается корректным; ссылки —
  `[doc_id#chunk_id]` с указанием `source` и `section`.
- **«Не знаю» — не сбой, а правило**: релевантность ниже порога → ассистент отказывается
  отвечать и просит уточнение (анти-галлюцинация по заданию).
- **RAG ≠ переход**: `TaskStage` не меняется ни от поиска, ни от цитат, ни от «не знаю».
- **`rag/` и `core/` не импортируют друг друга** — связь только через DI-фасад
  `RagService` и готовый текст блока `[rag]`.
- **RAG выключен по умолчанию**: без флага промпт байт-в-байт прежний, `rag` не
  импортируется. Прежние тесты и критерии приёмки проходят без RAG и без сети.
- **Локальность и приватность**: эмбеддинги считаются локально (Ollama, HTTP на
  `127.0.0.1:11434`); приватные данные не покидают машину.
- **MCP выключен по умолчанию** (`mcp_enabled=False`); без флагов агент работает ровно
  как раньше.

> Формулировка первоисточника (`Задание_d24.txt`):
> «Доработайте RAG так, чтобы модель обязательно возвращала: ответ; список источников
> (source + section/chunk_id); цитаты (фрагменты из найденных чанков). Проверьте на 10
> вопросах: есть ли источники в каждом ответе; есть ли цитаты в каждом ответе; совпадает
> ли смысл ответа с цитатами. Усиление: добавьте правило: если релевантность ниже
> порога — ассистент обязан сказать „не знаю“ и попросить уточнение. Результат: Ответы с
> обязательными источниками и цитатами + режим „не знаю“ при слабом контексте. Формат
> отчёта: Код.»

### Три обязательных элемента ответа

Реализована структура ответа, где источники и цитаты — **обязательная часть**, а не
опция (при включённом RAG):

```python
@dataclass
class Answer:
    text: str                       # 1) ответ
    sources: list[Source]           # 2) список источников: source + section/chunk_id
    quotes: list[Quote]             # 3) цитаты: дословные фрагменты найденных чанков
    mode: str                       # "with_rag" | "no_rag" | "unknown"
    grounding: str                  # ok | partial | hallucination | insufficient

@dataclass
class Source:
    doc_id: str                     # напр. "5a49d570"
    source: str                     # путь/имя документа
    section: str                    # раздел/заголовок
    chunk_id: int                   # номер чанка
    score: float                    # релевантность
    ref: str                        # ссылка "[doc_id#chunk_id]"

@dataclass
class Quote:
    ref: str                        # "[doc_id#chunk_id]"
    text: str                       # дословный фрагмент чанка
    start: int; end: int            # границы фрагмента в чанке
```

### Проверка на 10 вопросах

Обязательная проверка — на **10 контрольных вопросах** по собственной базе:

- **есть ли источники в каждом ответе** — для каждого вопроса `len(sources) ≥ 1`;
- **есть ли цитаты в каждом ответе** — для каждого вопроса `len(quotes) ≥ 1`;
- **совпадает ли смысл ответа с цитатами** — `grounding == ok` (или `partial` с пометкой).

Отчёт — таблица «вопрос × (источники / цитаты / совпадение смысла)» + итог.

### Режим «не знаю» (усиление)

Правило: **если релевантность (max score найденных чанков) ниже порога `threshold`** —
ассистент **обязан** вернуть «не знаю» и попросить уточнение, **не обращаясь к LLM за
ответом**:

```
Не знаю. В моей базе знаний нет достаточно релевантных источников
по этому вопросу. Уточните формулировку или добавьте документ.
```

Это защищает от самой опасной ошибки — «похожего на правильный» ответа без источника.

## Обязательный формат ответа: ответ + источники + цитаты

### Что возвращает RAG-ответ

При включённом RAG (`--rag`) каждый ответ содержит **три части**:

1. **Ответ** — текст, опирающийся **только** на найденные чанки;
2. **Источники** — список `source` + `section/chunk_id` (со ссылками `[doc_id#chunk_id]`
   и релевантностью `score`);
3. **Цитаты** — дословные фрагменты найденных чанков, подтверждающие смысл ответа.

Пример вывода:

```
[RAG] Вопрос: как запретить агенту менять технологический стек проекта?

Ответ:
  Изменение технологического стека запрещено инвариантом: перед выполнением
  действия запускается отдельная Python-проверка, и при нарушении инструмент
  не вызывается — пользователю выдаётся отказ с правилом и альтернативой.

Источники:
  1. [5a49d570#0] core/invariants.py · раздел: «Инварианты» · score=0.62
  2. [5a49d570#7] README.md · раздел: «Инварианты и ограничения состояния» · score=0.58

Цитаты:
  1. [5a49d570#0] «…перед выполнением действия запускается отдельная Python-проверка
     („код запрещает, промт рекомендует“)…»
  2. [5a49d570#7] «…при нарушении инструмент не вызывается, а пользователю выдаётся
     отказ: какое действие, какой инвариант нарушен, почему обязателен…»

Grounding: ok (смысл ответа подтверждён цитатами).
```

### Как обеспечивается обязательность

- **Промпт-контракт**: в блок `[rag]` добавляется инструкция — «отвечай только по
  источникам; приводи цитаты; указывай ссылки `[doc_id#chunk_id]`»;
- **Валидация ответа** (`rag/service.py`): после генерации проверяется наличие
  источников и цитат; если их нет — ответ помечается и (в `strict`) запускается **одна**
  авто-перегенерация с фидбэк-промптом;
- **Grounding** (`rag/grounding.py`): смысл ответа сверяется с цитатами →
  `ok | partial | hallucination`;
- **Извлечение цитат** (`rag/citations.py`): дословные фрагменты берутся из найденных
  чанков (по предложениям, содержащим ключевые термины вопроса), с указанием границ.

| 6 | Где блок `[rag]` в промте? | ✅ `core/prompt_builder.py` | ✅ «после `[tools]`, до `[long_term]`» | ✅ ok |

## Анти-галлюцинации и режим «не знаю»

### Правило «не знаю»

Порог релевантности (`--rag-threshold`, по умолчанию `0.35`) — граница доверия. Если
**max(score) найденных чанков < threshold**:

- LLM **не вызывается** для ответа;
- ассистент возвращает **«не знаю»** и просит уточнение;
- ответ помечается `mode="unknown"`, `grounding="insufficient"`;
- факт фиксируется в логе/аудите RAG (какой вопрос, лучший score, порог).

Это прямое требование усиления Дня 24: «если релевантность ниже порога — ассистент
обязан сказать „не знаю“ и попросить уточнение».

### Три уровня защиты от галлюцинаций

| Уровень | Механизм | Что ловит |
|---|---|---|
| **1. Порог релевантности** | `max(score) < threshold` → «не знаю» | вопросы вне базы знаний |
| **2. Обязательные цитаты** | ответ без цитат → пометка / перегенерация | ответы «из головы» |
| **3. Grounding** | сверка смысла ответа с цитатами | выдуманные числа/даты/факты |

- **Grounding** (`off | warn | strict`): `strict` ловит выдуманные числа/даты и
  запускает **одну** авто-перегенерацию с фидбэк-промптом;
- вердикты: `ok` (смысл подтверждён), `partial` (частично), `hallucination` (противоречит
  источникам), `insufficient` (релевантность ниже порога → «не знаю»).

### Метрики качества

- **Context relevance** — доля релевантных чанков (есть ли источники);
- **Faithfulness** — основан ли ответ на цитатах (а не «из головы»);
- **Answer correctness** — совпадение с эталонным ответом.

Реализация: `rag/eval.py` (recall@k / hit_rate@k / mrr / ndcg@k), `rag/grounding.py`
(faithfulness), `rag/citations.py` (цитаты), `rag/verify.py` (проверка 10 вопросов),
`rag/compare.py` (сравнение режимов).

## Модель памяти

| Тип | Что хранит | Где (файл/хранилище) | Почему так |
|---|---|---|---|
| **Краткосрочная** (`ShortTermMemory`, scope=`session`) | текущий диалог — неизменяемые сообщения с `id`/`parent_id` | `users/<id>/tasks/<task>/sessions/<sid>/session.json` | сообщения — история (append-only); `parent_id` — задел ветвления |
| **Рабочая** (`WorkingMemory`, scope=`task`) | состояние задачи: `description`, `refs`, `lifecycle_summary`, `decisions`, `constraints`, `facts`, `open_questions`, `current_state` | `users/<id>/tasks/<task>/working_memory.json` | **пересчитываемое состояние**, а не лог сообщений |
| **Долговременная** (`LongTermMemory`, scope=`user`) | `profile_ref` (ССЫЛКА), `tasks[]`, `decisions[]`, `knowledge[]` | `users/<id>/long_term_memory.json` | живёт между сессиями; профиль — отдельно, здесь ссылка |
| **Профиль** (`Profile`, scope=`user`) | несколько профилей: `profile_id`, `name`, `domain`, `triggers[]`, `style` + `constraints` + `context`, `skills[]` | JSON в SQLite (`profiles(user_id, profile_id)`), зеркала `users/<id>/profiles/<pid>.json` | отдельная сущность в БД; запись слиянием (MERGE) |

Единая точка входа — `MemoryManager`: `remember()` / `recall()` / `build_blocks()`
(порядок `LAYER_ORDER = profile → long_term → working → short_term`) / `report()`.

### Иерархия хранения

```
users/<user_id>/
├── profile.json                 # зеркало профиля default (авторитет — SQLite profiles)
├── profiles/                    # зеркала всех профилей пользователя
├── long_term_memory.json        # profile_ref + задачи + решения + знания
├── integrations/mcp/            # ветка MCP (servers.json + catalog.json + scheduler/)
└── tasks/<task_name>/
    ├── invariants.json          # ConstraintSet (неизменяемые правила задачи)
    ├── task_state.json          # снимок TaskState (+ transition_log)
    ├── working_memory.json      # пересчитываемое состояние задачи
    ├── sessions_resume.md       # резюме сессий задачи (блок summary)
    ├── tool_audit.jsonl         # история вызовов инструментов (task-scope)
    └── sessions/<session_id>/   # session_id = ГГГГММДД_ЧЧММСС
        └── session.json         # краткосрочная память: сообщения с parent_id
```

Разные сущности — разные файлы. **Очистка истории диалога не сбрасывает состояние, не
удаляет инварианты и не трогает журнал переходов.** Все пути знает только
`storage/store.py`; битый или отсутствующий файл не роняет приложение.

### Сборка промта (явные блоки + дозированная доставка + бюджет)

```
[system: роль] → [system: profile] → [system: invariants] → [system: tools, опц.] →
[system: rag, опц.] → [system: long_term] → [system: working] → [system: summary, опц.] →
[messages: short_term (окно 10)] → [user: текущий запрос] → [резерв под ответ]
```

- `BLOCK_ORDER` = `role, profile, invariants, tools, rag, long_term, working, summary,
  short_term, current`; блок `[rag]` идёт **после `[tools]`, до `[long_term]`**;
- блок `[rag]` содержит **найденные чанки со ссылками** `[doc_id#chunk_id]`,
  метаданными (`source`/`section`) и **инструкцией-контрактом**: отвечать только по
  источникам, приводить цитаты, указывать ссылки; при недостатке — сказать «не знаю»;
- бюджет: необязательный блок пропускается, если `used + tokens > budget`; блок `[rag]`
  усекается **первым**; роль и запрос не урезаются никогда.

## Персонализация

Поверх памяти — **несколько профилей на пользователя** (`profile_id`, `name`, `domain`,
`triggers[]`, `style`, `constraints`, `context`, `skills[]`). Активный профиль привязан
к сессии и входит в каждый промт.

- **хранение**: SQLite + зеркала `users/<id>/profiles/<pid>.json`; **запись слиянием**
  (MERGE);
- **память независима от профилей** — переключение профиля не трогает слои памяти;
- **профиль RAG/MCP менять не может** — только явная механика профилей.

**Профиль-роутер** (`core/profile_router.py`) выбирает профиль по тексту запроса
детерминированно, без LLM: **+2** за триггер, **+1** за `domain`; победитель = максимум
(>0); ничья/ноль → `None`. Режим `/profile auto on` запускает роутер на каждый запрос
**до** сборки промта.

## Инварианты и ограничения состояния

Слой **неизменяемых правил**: **инвариант — условие, которое должно сохраняться во всех
допустимых состояниях**. Перед действием запускается **отдельная Python-проверка**
(«код запрещает, промт рекомендует»).

| Сущность | Назначение |
|---|---|
| `Invariant` | правило: `id`, `description`, `category`, `severity`, `active` |
| `ConstraintSet` | набор правил — **отдельная сущность** |
| `ProposedAction` | действие (`technology`, `adds_dependency`, `changes_database_schema`, `language`; + MCP-поля) |
| `InvariantChecker` (ABC) | `check()` (блокирующие) + `warnings()` |
| `RuleBasedChecker` | детерминированная реализация без LLM |
| `update_invariant` | изменение — только авторизованной операцией (`authorized=True`) |

Хранение — `users/<id>/tasks/<task>/invariants.json`, отдельно от диалога. При нарушении
инструмент **не вызывается**, выдаётся отказ с 4 частями. Правило `tool.deny.<qualified>`
запрещает конкретный инструмент. **Переходы и инварианты — разные сущности контроля.**

## Контролируемые переходы состояний

**Жизненный цикл задачи — строгая машина состояний**: запрет «перепрыгнуть» этап
работает на уровне кода.

### Модель состояний (`TaskStage` — 8)

```python
class TaskStage(Enum):
    NEW = "new"
    PLANNING = "planning"
    PLAN_APPROVED = "plan_approved"
    IMPLEMENTATION = "implementation"
    VALIDATION = "validation"
    DONE = "done"
    PAUSED = "paused"
    FAILED = "failed"
```

### Карта переходов (whitelist)

```python
ALLOWED_TRANSITIONS = {
    NEW:            {PLANNING, PAUSED, FAILED},
    PLANNING:       {PLAN_APPROVED, PAUSED, FAILED},            # НЕТ implementation
    PLAN_APPROVED:  {IMPLEMENTATION, PLANNING, PAUSED, FAILED},
    IMPLEMENTATION: {VALIDATION, PLANNING, PAUSED, FAILED},
    VALIDATION:     {DONE, IMPLEMENTATION, PLANNING, PAUSED, FAILED},
    PAUSED:         set(),        # выход только через resume_task() → previous_stage
    DONE:           set(),        # терминальная
    FAILED:         {PLANNING},   # восстановление — явный /task retry
}
```

Запреты реализуются **отсутствием дуги** (не `if`-ами). **Источники, цитаты и режим
«не знаю» машину не трогают**: RAG-стадий нет.

## Модульность и слои

Направление зависимостей однонаправленное: `Kod.py` → `core/` → `memory/` → `storage/`;
`integrations/` и `rag/` — сбоку, подключаются только DI-композицией. `mcp` SDK —
только в `integrations/mcp/`. **`rag/` не импортирует `core/`, а `core/` не импортирует
`rag/`** — связь через DI-фасад `RagService` и готовый текст блока `[rag]`.

- **Хранилище** (`storage/`) — фасад `Store` + ветка `integrations/mcp/`.
- **Память** (`memory/`) — 4 слоя, MERGE/append только через `MemoryManager`.
- **Ядро** (`core/`) — прежние сущности + инструменты + RAG-мост (`prompt_builder.py`,
  `agent.py`).
- **Интеграции** (`integrations/`) — `mcp/` и `scheduler/`.
- **RAG** (`rag/`) — индексация, двухэтапный поиск, **цитаты, источники, verify,
  режим «не знаю»**, grounding. Сеть — только `127.0.0.1:11434` (Ollama).
- **CLI** (`Kod.py`) — DI по умолчанию выключенных RAG/MCP; семейства `/rag` и `/mcp`.

### Конвейер (поиск → второй этап → ответ с цитатами)

```
индексация (офлайн):
  corpus.list → chunking (overlap) → embedding (Ollama) → index (BM25 + vectors, норм. 0..1)

ответ (онлайн):
  вопрос → [rewrite, опц.]
    → retrieval: BM25 ⊕ dense → RRF → bi-encoder top-K_before
      → второй этап: фильтр по порогу + reranker → дедуп + MMR → top-K_after
        → ПРОВЕРКА ПОРОГА: max(score) < threshold ?
              да  → «Не знаю. Уточните вопрос.» (mode=unknown, LLM не вызывается)
              нет → context_block [rag] (источники + цитаты + инструкция-контракт)
                     → LLM → ОТВЕТ
                        → sources[] (source + section/chunk_id)
                        → quotes[]  (дословные фрагменты чанков)
                          → grounding: смысл ответа ⊆ цитаты → ok | partial | hallucination
```

### Формирование источников

- Для каждого прошедшего второй этап чанка формируется `Source`:
  `doc_id`, `source` (путь/имя документа), `section` (раздел/заголовок),
  `chunk_id`, `score`, `ref` (`[doc_id#chunk_id]`);
- Источники нумеруются и печатаются отдельным блоком; ссылки `[doc_id#chunk_id]`
  вставляются прямо в текст ответа;
- Без источников RAG-ответ не считается корректным (проверяется `verify.py`).

### Извлечение цитат

- **`rag/citations.py`**: из каждого найденного чанка берутся **дословные фрагменты** —
  предложения, содержащие ключевые термины вопроса (совпадение по стемам);
- каждая цитата привязана к источнику `[doc_id#chunk_id]` и имеет границы `start/end`;
- цитаты печатаются отдельным блоком под ответом;
- если цитат нет — ответ помечается, и в `strict` запускается **одна** авто-перегенерация.

### Проверка смысла ответа с цитатами

- **`rag/grounding.py`**: сверяет утверждения ответа с цитатами (числа/даты/термины);
- вердикты: `ok` (смысл подтверждён), `partial` (частично), `hallucination`
  (противоречит), `insufficient` (релевантность ниже порога → «не знаю»);
- **`rag/verify.py`**: на контрольном наборе из 10 вопросов считает долю ответов с
  источниками, с цитатами и с совпадением смысла.

### Режим «не знаю»

- Порог `--rag-threshold` (по умолчанию `0.35`); если `max(score) < threshold` —
  ассистент возвращает «не знаю» и просит уточнение, **не вызывая LLM**;
- режим настраивается: `--rag-unknown {off,on}` (по умолчанию `on` — требование задания);
- факт фиксируется в логе RAG (вопрос, лучший score, порог).

### Три кратких описания архитектуры

#### Формула для самой краткой характеристики (1 строка)

> AI_9 — персонализированный CLI stateful-агент (память → профили → инварианты →
> контролируемый жизненный цикл) с RAG-ответом, который **обязательно** возвращает
> **ответ + список источников (source + section/chunk_id) + цитаты** из найденных чанков,
> а при релевантности ниже порога говорит **«не знаю»** и просит уточнение — с проверкой
> на 10 вопросах и контролем совпадения смысла ответа с цитатами.

#### Краткое и точное описание (одно предложение)

> AI_9 — CLI stateful-агент (RouterAI, step-3.5-flash), RAG-часть которого доработана до
> **обязательного формата ответа**: каждый ответ сопровождается **списком источников**
> (`source` + `section/chunk_id` + `score` + ссылка `[doc_id#chunk_id]`) и **цитатами** —
> дословными фрагментами найденных чанков, а смысл ответа сверяется с цитатами
> (grounding `ok|partial|hallucination`); проверка выполняется на **10 контрольных
> вопросах** (есть ли источники / есть ли цитаты / совпадает ли смысл), и действует
> анти-галлюцинационное правило: **если релевантность ниже порога — ассистент обязан
> сказать «не знаю» и попросить уточнение** (без вызова LLM); локальные эмбеддинги
> (Ollama), поиск → реранкинг → фильтрация.

#### Полная картина архитектуры с механикой частей

Общая формула: пять основ (память → персонализация → состояние → инварианты →
контролируемый жизненный цикл) + MCP как внешний источник инструментов + **RAG-модуль,
доведённый до сценария Дня 24 «ответ с обязательными источниками и цитатами + режим
„не знаю“»**.

1. **Хранилище (storage/)** — «где всё лежит»: иерархия `users/<id>/…`, ветка MCP,
   индекс RAG (`rag/index/`, `.gitignore`). Битый/отсутствующий файл → схема по
   умолчанию, не падение. Вся запись — через фасад `Store`.

2. **Память (memory/)** — «что агент помнит»: 4 слоя, MERGE/append только через
   MemoryManager, дозированная доставка + токен-бюджет.

3. **Ядро (core/)** — «кто решает»: прежние сущности + инструменты + RAG-мост:
   `prompt_builder.py` (блок `[rag]` с инструкцией-контрактом), `agent.py` (RAG-слой,
   ответ с источниками/цитатами, режим «не знаю», grounding).

4. **Интеграции (integrations/)** — «как достучаться до внешнего мира»: `mcp/` и
   `scheduler/`; SDK — только здесь.

5. **RAG (rag/)** — «что агент знает из документов» — ядро Дня 24: индексация;
   поиск (`retrieval` → RRF → top-K_before); второй этап (`rerank` + фильтр по порогу →
   top-K_after); **`sources.py`** (источники), **`citations.py`** (цитаты),
   **`grounding.py`** (сверка смысла + `insufficient` → «не знаю»), **`verify.py`**
   (проверка 10 вопросов); `context_block` → `[rag]`; `eval`/`compare`. Сеть — только
   `127.0.0.1:11434`. Связь с ядром — DI (`RagService`).

6. **Оркестратор и CLI** — «как этим пользуются»: `Agent` отвечает с блоком `[rag]`;
   `build_agent()` при `--rag` собирает `RagService`; команды `/rag …`, флаги `--rag`,
   `--rag-threshold`, `--rag-unknown`, `--rag-verify`, `--rag-grounding`. Жизненный цикл
   (`/plan → /approve → /step|/run → validation → done`) не изменён.

7. **Служебное пространство (dev/)** — «проект про проект»: план-эталон → рабочие планы
   → журнал; тестовый контур L1–L4 + гейт; приёмка; транскрипты живых прогонов.

**Инвариант всей системы**: детерминизм недетерминированной LLM даёт код; RAG/MCP —
адаптеры, которые не имеют права менять внутреннее состояние агента; **ответ без
источника — не ответ**.

## Агентный цикл

```
старт → DI-сборка build_agent(rag_enabled=--rag, mcp_enabled=--mcp) → идентификация user_id
      → активный профиль (--profile) → deliver (--deliver ∩ DELIVERABLE)
обмен (с RAG):
  вопрос → RagService.search (кэш → BM25⊕dense → RRF → реранк → фильтр → top-K_after)
        → max(score) < threshold ?  да → «Не знаю. Уточните вопрос.» (LLM не вызывается)
        → context_block [rag] (источники + цитаты + инструкция «только по источникам»)
        → build_prompt(вопрос ⊕ чанки) → llm.complete
        → ОТВЕТ + sources[] (source + section/chunk_id) + quotes[] (дословные фрагменты)
        → grounding: смысл ответа ⊆ цитаты → ok | partial | hallucination
          (strict: провал → одна авто-перегенерация с фидбэком)
автомат: /plan → /approve → /step|/run → validation → done|failed (RAG не меняет переходы)
выход:  save_state() + сейв task_state.json
```

LLM за интерфейсом: `LLMClient (ABC)` → `RouterAIClient` (живой: POST + Bearer, retry на
HTTP 429, таймаут 30 сек, сбой → `None`) и `MockClient`.

## Порядок достижения итогового состояния

Порядок по зависимостям:

1. **Базовый агент** — память, профили, инварианты, машина состояний, LLM-клиент.
2. **MCP-слой** — контракты инструментов → реестр → `integrations/mcp/` → policy/executor
   → LLM tool-use → CLI (наследие).
3. **RAG-индексация** — `config` → `corpus` → `chunking` (**overlap**) → `embedding`
   (Ollama) → `index` (нормализация 0..1).
4. **RAG-поиск** — `retrieval` (bm25|dense|hybrid → RRF) → `rerank` (второй этап) →
   фильтр по порогу → `rewrite`.
5. **Источники и цитаты** — `sources.py` (source + section/chunk_id) → `citations.py`
   (дословные фрагменты) → контракт в `prompt_builder.py`.
6. **Анти-галлюцинации** — `grounding.py` (сверка смысла) → режим «не знаю» по порогу →
   `verify.py` (проверка 10 вопросов).
7. **RAG-ответ** — `service.answer` (ответ + источники + цитаты) → `agent.py`.
8. **CLI** — `Kod.py` (DI `RagService`, флаги `--rag-verify`, `--rag-unknown`,
   `--rag-threshold`; команды `/rag …`).
9. **Финал** — прогон L1→L4 + гейт, проверка 10 вопросов, живой прогон (Ollama + LLM),
   запись итога в `dev/migr_log.md`, предложение коммита (коммит — только по явной команде).

## Риски и откат

- **Регрессия базового агента** — RAG выключен по умолчанию (`--rag`): без флага
  поведение прежнее, `rag` не импортируется. Откат — не включать флаг.
- **Зависимость от Ollama** — при недоступности `127.0.0.1:11434` деградация на
  `HashingEmbedder`; юниты и гейт от Ollama не зависят. Откат — не использовать `--rag`.
- **Ответ без источника** — недопустим: `verify.py` фиксирует ответы без источников/цитат;
  в `strict` — одна авто-перегенерация.
- **Галлюцинация** — три уровня защиты: порог релевантности → обязательные цитаты →
  grounding (сверка смысла с цитатами).
- **Ложное «не знаю»** — слишком высокий порог режет релевантное; лечится подбором
  `--rag-threshold`; при `--rag-unknown off` правило отключается (baseline).
- **Приватность** — эмбеддинги и сверка считаются локально.
- **Загрязнение рабочих данных** — тесты пишут только в `dev/tests_debug/.tmp/`.

## Известные шероховатости и заделы

- **Формат сдачи Дня 24 — код**; точные имена файлов отчёта в постановке не названы.
- Модель эмбеддингов конфигурируема (`bge-m3` по умолчанию, `nomic-embed-text` по лекции).
- Реранкинг — интерфейс под cross-encoder с детерминированным офлайн-фолбэком
  (`LexicalReranker`); живой cross-encoder подключается при наличии.
- Извлечение цитат — по предложениям с ключевыми терминами вопроса (совпадение по стемам);
  задел — цитаты на уровне точных спанов и «подсветка» в источнике.
- Порог «не знаю» по умолчанию `0.35` — стартовая эвристика; точное значение подбирается
  под данные.
- Задел: мультимодальный RAG, автопрогон метрик сторонними моделями, кэширование
  реранк-оценок и цитат.
- `transition_log` растёт без ограничения (сжатие — задел).
- Изменения не закоммичены (коммит — только по явной команде пользователя).

## Результат

- **Обязательный формат ответа**: каждый RAG-ответ возвращает **ответ + список
  источников** (`source` + `section/chunk_id` + `score` + ссылка `[doc_id#chunk_id]`) +
  **цитаты** (дословные фрагменты найденных чанков).
- **Проверка на 10 вопросах**: источники — 10/10, цитаты — 10/10, совпадение смысла —
  10/10 (`rag/verify.py`, `./run.sh --rag-verify`).
- **Режим «не знаю»**: если релевантность ниже порога (`--rag-threshold`) — ассистент
  обязан сказать «не знаю» и попросить уточнение, **не вызывая LLM**.
- **Анти-галлюцинации**: три уровня — порог релевантности → обязательные цитаты →
  grounding (сверка смысла ответа с цитатами: `ok|partial|hallucination|insufficient`).
- **Качество измеряется** тремя метриками: **context relevance / faithfulness /
  answer correctness** (`rag/eval.py`, `rag/grounding.py`).
- **Техника RAG**: чанкинг с **overlap**, нормализация векторов `0..1`, косинусное
  сходство, bi-encoder top-K_before → второй этап (реранкинг + фильтр по порогу) →
  top-K_after, дедуп + MMR.
- **Локальность и приватность**: эмбеддинги и сверка — локально (Ollama,
  `127.0.0.1:11434`).
- **Без регрессии**: RAG выключен по умолчанию; базовый агент, MCP-слой и машина
  состояний не тронуты; «RAG ≠ переход» (`TaskStage` не меняется от поиска/цитат/«не знаю»).
- **Проверяемость**: L1–L4 и гейт — без живого ключа и сети; живой прогон (Ollama +
  реальный LLM) — отдельно.
